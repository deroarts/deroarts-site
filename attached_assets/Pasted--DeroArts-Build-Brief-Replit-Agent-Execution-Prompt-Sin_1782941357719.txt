# A. WORKING BRIEF (context & confirmed decisions — keep updated)

## A.1 What DeroArts is
A public **showcase / storefront** where non-technical visitors browse small software and apps
("gestionali" and utilities), read about each one, **try a live demo** via a link, and **request
information**. Plus a private **admin** (only the owner) to publish projects and manage the
incoming requests. Official domain: **deroarts.com**.

## A.2 Audience & tone
- Visitors are **non-technical, small/medium users**. Zero jargon. Simple Italian labels.
- Public site must be **beautiful, welcoming, intuitive** — a real modern showcase, **NOT** a
  clone of the admin (the admin is a management tool).

## A.3 Scope
**In scope (this build, on Replit):** full public site + admin + "request info" flow with
**fake email** in dev; portable, standard code; DB schema and handoff docs shaped for Supabase.
**Out of scope (done later, in Devin/Claude):** GitHub, real Supabase, Render deploy, real Zoho
email wiring, and the owner's separate governance/DNA/responsive prompts. **Do not add those here.**

## A.4 Confirmed decisions
- **Public pages:** Home · Projects (filterable grid) · Project detail · Contact/Info.
- **Project fields:** title, short description, long description, cover image, gallery, category,
  status, actions (buttons).
- **Actions (buttons)** with friendly IT labels: `demo` → "Prova la demo"; `request_info` →
  "Richiedi informazioni" (opens the form). Future, predisposed but hidden until filled:
  `download`, `app_store`, `play_store`. Data model supports **multiple actions per project**;
  the UI shows only friendly buttons (never technical terms like GitHub/repo).
- **Request info flow:** in-site form → saves a request (status `new`/`read`/`handled`, linked to
  the project) → sends notification to owner + **auto-reply** to the user (with the project's
  identity). Admin shows per-project request counts and an **unread bell**.
- **Admin (`/admin`, single owner):** left **sidebar on desktop**, **slide-in drawer on mobile**;
  visual language inspired by "App Control" but a bit more professional (more whitespace, cleaner
  type). Login **email + password**, **"remember me" persistent** by default.
- **Categories:** a **managed list** (own table); create/rename in admin, pick from a menu on a
  project; used for public filtering.
- **Images:** fixed, consistent **aspect-ratio placeholders** (identical in admin and public);
  on upload, an **in-frame editor** to **zoom + reposition (drag, 360°)** so the crop is perfect;
  what the admin sees is exactly what the user sees.
- **Preview:** an **"Anteprima" button** that opens the public preview of the project being edited
  (structure ready to evolve into a side-by-side live preview later).
- **Dev U/A switch:** a fixed, always-visible button to jump between **User** and **Admin** during
  development, outside login/privacy — **isolated, env-gated, removable** (see B rules). Owner
  removes it once the project is consolidated.
- **Language:** UI is Italian. **Public content is multilingual-ready (it/en) in the schema**
  (English fields empty for now). **Admin is Italian only** — no multilingual UI in admin.

## A.5 Data model (Postgres / Supabase-ready)
Translatable text fields use a **JSONB** shape `{ "it": "...", "en": "" }` (admin fills `it`;
`en` stays empty; UI reads `it` with fallback). This is the multilingual-ready design.

- **categories**: `id`, `name` (jsonb), `slug`, `sort_order`, `created_at`.
- **projects**: `id`, `slug`, `title` (jsonb), `short_description` (jsonb), `long_description`
  (jsonb), `status` (`available` | `coming_soon` | `demo_available`), `category_id` (fk),
  `cover_image_url`, `gallery` (jsonb array of `{ url, alt (jsonb) }`), `published` (bool),
  `sort_order`, `from_email` (nullable; default `info@deroarts.com` — per-project alias hook),
  `created_at`, `updated_at`.
- **project_actions**: `id`, `project_id` (fk), `type` (`demo`|`request_info`|`download`|
  `app_store`|`play_store`|`external`), `label` (jsonb), `url` (nullable; null for `request_info`),
  `enabled` (bool), `sort_order`.
- **requests**: `id`, `project_id` (nullable fk — null = general contact from Contact/Info page),
  `name`, `email`, `message`, `status` (`new`|`read`|`handled`), `created_at`, `handled_at`
  (nullable).
- **dev_outbox** (dev only): `id`, `to`, `from`, `subject`, `body`, `created_at` — lets the admin
  view the fake emails during development.

Images: files live in **storage** (local folder in dev, Supabase Storage in prod); the DB stores
only the **URL/path**.

## A.6 Non-negotiable constraints
- **Free-tier friendly:** target Supabase Free + Render Free. Optimize/compress images on upload,
  lazy-load, no always-on background processes, lightweight code (Render Free sleeps when idle).
- **No vendor lock-in to Replit:** standard, portable code only. No Replit-only libraries/magic.
- **No PWA. No Expo / React Native.** Public site is a **normal responsive website** (mobile feel
  achieved with standard CSS/responsive). `/admin` is just a protected route (not installable).
- **DB is the single source of truth** for content; admin and public read the same data.
- **Adapters** for DB, storage, and email so dev→prod is a config/adapter swap, not a rewrite.

# B. EXECUTIVE PROMPT FOR REPLIT AGENT

You are building **DeroArts**, described above. Follow these rules and build **module by module**.

## B.0 Global rules (read first, apply throughout)
- **Work in modules, in order.** For each module: switch to **Plan Mode**, propose a short plan,
  **wait for my approval**, then Build. **Create a checkpoint** after each module.
- **Build exactly this spec. Do not add features that aren't requested.** If something is
  genuinely ambiguous, ask **at most 2 questions**, otherwise proceed.
- **Positive constraints:** keep files small and modular, reuse logic, clear naming.
- Keep the code **portable and standard** (no Replit-only dependencies).
- **Do not** set up GitHub, real Supabase, Render, real email, or any governance/DNA files — those
  are handled later. Your job is the app + Supabase-ready schema + handoff docs.

## B.1 Fixed tech stack
- **Next.js (App Router, React, TypeScript)** — one full-stack app serving both public and `/admin`.
- **Prisma ORM + PostgreSQL.** In dev, use the **Postgres provided by Replit** via `DATABASE_URL`.
  In prod, the same schema points to **Supabase Postgres** (only `DATABASE_URL` changes).
  > Use **Postgres from the start (not SQLite)** so the multilingual JSONB fields and JSON gallery
  > migrate to Supabase with **zero rework**.
- **Tailwind CSS** for styling, with brand tokens (see B.2).
- **Adapters (interfaces + swappable implementations):**
  - *Storage:* `local` (writes to a served uploads folder, stores the URL in DB) now → `supabase`
    (Supabase Storage) later. Selected by `STORAGE_MODE`.
  - *Mail:* `fake` (logs to console + writes to `dev_outbox`, viewable in admin) now → `smtp`
    (Zoho) later. Selected by `MAIL_MODE`.
  - *Auth:* email+password with a signed session cookie now → Supabase Auth later.
- All secrets/config via **environment variables** (provide a documented `.env.example`).

## B.2 Brand & design direction
- **Palette:** graphite `#1A222B`; green gradient `#8FC603 → #1E9E3D` (accent); dark green surface
  `#1A3A26 → #0F2419`; light surface `#F8F6F6`. **Font: Poppins.**
- **Public site:** modern, attractive **showcase** — hero, curated **card grid**, large images,
  light micro-interactions, generous spacing. Distinct and appealing, **not** an admin clone.
- **Admin:** **sidebar on desktop**, **slide-in drawer on mobile**, "App Control" style but more
  professional/clean. Use the attached App Control screenshot as the reference.
- Use the attached logo/symbol/favicon assets (see § ASSETS).
